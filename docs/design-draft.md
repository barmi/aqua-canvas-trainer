- 작성일: 2026-10-09
- 상태: 초안 v0.2 — MVP 구현 상태 반영
- 대상: iPad Safari와 Apple Pencil을 중심으로 하는 웹 앱
- 구현: 배경 6종, 펜 엔진, 지원 조명 264조합, 5단계 가이드, 저장·내보내기, PWA
- 실기기: 사용자 iPad/Pencil 기본 동작 확인으로 #7 종료. 필압 체감 개선은 #8
- 추가 검증: 수정 후 필압 체감, HTTPS 설치·오프라인, 성능 수치 ([기록](device-test-checklist.md))

## 1. 제품의 목표

같은 선화와 바탕색을 가진 장면을 여러 조명 조건에서 직접 채색하며
빛의 방향, 명도, 색온도, 그림자와 수채화의 겹칠하기를 익히게 한다.
사용자는 완성 이미지를 자동으로 받는 대신, 안내된 영역과 팔레트를
참고해 Apple Pencil로 직접 칠한다.

시작점은 [참고 영상](https://x.com/gwamoleipstop/status/2108414480417972370)의
의자·식물이 있는 실내 장면이다. 영상에서는 이미 그려진 선화에 노란
바탕색을 입히고, 식물과 가구의 색·음영을 더하는 과정이 보인다.
이 흐름을 **바탕색 → 큰 색면 → 그림자 → 겹칠하기 → 디테일**의 연습으로 옮긴다.

여기서 ‘기본 배경’은 사용자가 그 위에 칠할 수 있는 **선화 + 초기 바탕색**이다.
색을 전부 칠한 참고 완성작과 구분한다. 종이 질감만 있는 빈 캔버스도
추후 자유 연습 모드로 제공할 수 있다.

## 2. 사용자 경험과 화면

1. 배경을 고른다. 미리보기, 난이도, 연습 목표를 확인한다.
2. 새벽·오전·오후·저녁·밤 중 시간대를 고른다.
3. 장면에서 지원하는 광원 종류와 방향을 고른다.
4. 빛의 방향 화살표, 주요 밝은 면·그늘, 추천 팔레트를 미리 본다.
5. 단계별 설명을 보면서 직접 칠한다. 힌트의 표시와 투명도를 조정한다.
6. 가이드를 끄고 결과를 비교하거나 같은 배경의 다른 조건으로 다시 연습한다.
7. 연습을 저장하고, 이어 그리거나 PNG와 편집 가능한 프로젝트 파일로 내보낸다.

### 화면 구성

| 화면 | 주요 내용 |
| --- | --- |
| 배경 라이브러리 | 준비된 배경, 난이도, 연습 목표, 참고 영상 |
| 연습 설정 | 시간대, 광원 종류, 방향, 지원 조건 미리보기 |
| 작업 공간 | 캔버스, 붓·팔레트, 가이드, 실행 취소/다시 실행 |
| 나의 연습 | 저장 목록, 썸네일, 이어 그리기, 결과 비교와 내보내기 |

아이패드 가로 모드는 중앙 캔버스, 한쪽 도구막대, 반대쪽 가이드 패널로
구성한다. 세로 모드는 가이드를 접을 수 있는 하단 패널로 배치한다.
도구 터치 영역은 44 CSS px 이상을 목표로 하고, 왼손잡이 배치를 지원한다.
화면 회전이나 패널 변경은 그림 데이터와 캔버스 좌표를 바꾸지 않는다.

현재 `App.tsx`는 풍경 선택·작업 공간·나의 연습을 연결한다. 설정은 작업 공간에
있으며 빛을 바꾸면 새 연습을 만든다. 여러 결과의 동시 비교 화면은 후속 범위다.

## 3. 배경 콘텐츠 계획

| ID | 배경 | 난이도 | 학습 내용 |
| --- | --- | --- | --- |
| `reference-plant-room` | 영상 속 의자와 식물이 있는 실내 | 중급 | 전체 워시, 가구 음영, 겹칠하기 |
| `window-still-life` | 창가의 컵·화분·천 | 초급 | 종이의 흰 부분, 부드러운 창문 빛 |
| `cafe-corner` | 카페 테이블과 의자 | 중급 | 실내등과 자연광, 색의 온도 |
| `garden-path` | 나무 사이 정원길 | 중급 | 나뭇잎의 번짐, 얼룩진 그림자 |
| `lakeside` | 하늘과 호숫가 | 초급 | 그라데이션, 수면 반사, 시간대 |
| `old-town-street` | 작은 마을 골목 | 고급 | 건물의 면, 긴 그림자, 원근 |

현재 카탈로그의 6종은 모두 직접 작성한 SVG 자산과 마스크를 가진 `ready` 상태다.
먼저 실내·정물·호숫가를 구현한 뒤 카페·정원·골목을 별도 이슈로 확장했다.

### 배경 한 종의 구성

- `line-art.svg` 또는 투명 PNG: 배율에 맞춰 표시하는 선화. 굵기 3단계의 펜 선으로
  윤곽·구조·질감을 그리고, 뒤에서 앞으로 쌓은 레이어의 실루엣으로 겹침을 가린다.
- `base-wash.svg`: 영상의 노란 바탕처럼 시작 시 제공하는 옅은 색면.
- `thumbnail.svg`: 배경 선택용 이미지.
- `masks/`: 의자, 화분, 식물, 바닥 등 의미 단위의 영역 마스크.
- `guides/`: 지원하는 조명 조건의 밝은 면·그림자·하이라이트 안내 이미지.
- 도메인 메타데이터: 논리 캔버스 크기, 버전, 영역 ID, 대응 가이드 ID.

선화·바탕색·마스크는 동일한 캔버스 크기와 원점을 사용한다.
종이 질감은 별도 공용 자산으로 합성한다. 선화와 바탕색은 보호하고,
사용자의 채색은 별도 레이어에 저장한다. ‘바탕색부터 연습’ 모드에서는
초기 바탕색을 숨기고 동일한 워시 단계를 안내한다.

### 영상 속 배경의 제작 방식

영상 프레임에는 손과 붓, 기울어진 종이, 이미 칠한 부분이 포함된다.
프레임을 그대로 배경으로 사용하면 칠하기 영역과 좌표가 맞지 않는다.
장면을 참고해 정면 구도의 선화를 정리하고, 바탕색과 영역 마스크를
별도로 제작한다. 원본 영상은 참고 재생용으로 보존한다.

## 4. 조명과 시간대 모델

조명은 장면의 기본색을 바꾸는 필터에 그치지 않고, 칠할 면과 남길 면,
그림자의 방향과 가장자리, 팔레트, 채색 순서를 함께 바꾸어야 한다.

| 항목 | 초안 |
| --- | --- |
| 광원 종류 | 태양 `sun`, 흐린 하늘 `sky`, 달 `moon`, 창문 `window`, 실내등 `lamp` |
| 방향 | 캔버스에서 광원이 있는 방향. 위 0°, 오른쪽 90°, 아래 180°, 왼쪽 270° |
| 광원 높이 | 장면 수평선 기준 0°부터 머리 위 90°까지 |
| 광량 | 학습용 상대 강도 0–1 |
| 광색 | sRGB 색상. 필요할 때 색온도를 보조 설명으로 표시 |
| 그림자 경계 | 부드러움 0–1 |
| 주변광 | 주광원과 별도의 색상·상대 강도 |

방향은 실제 동서남북과 연결하지 않는다. 시간대 선택은 교육용 시작값이며
날짜·위치에 따른 실제 태양 위치를 계산하지 않는다.

### 시간대별 시작 가이드

| 시간대 | 빛과 분위기 | 연습 안내 |
| --- | --- | --- |
| 새벽 | 낮은 대비, 차가운 주변광, 옅은 분홍 기운 | 차가운 바탕을 얇게 깔고 밝은 부분을 남긴다 |
| 오전 | 맑은 자연광 또는 창문 빛 | 밝은 면을 보존하고 그늘을 옅게 나눈다 |
| 오후 | 비교적 높은 광원과 강한 명암 | 큰 색면을 먼저 나누고 그림자를 겹친다 |
| 저녁 | 낮은 따뜻한 빛과 긴 그림자 | 주황빛과 차가운 그늘을 대비시킨다 |
| 밤 | 차가운 주변광과 달빛 또는 실내등 | 어두운 워시 위에서 제한된 밝은 부분을 살린다 |

`lighting-presets.ts`의 5종은 시작값이다. 오전의 창문 빛은 실내 장면에,
밤의 실내등은 실내 장면에 적합하다. 야외 장면에는 태양·하늘·달빛에
해당하는 장면별 레시피를 연결한다. 모든 광원과 배경의 조합을
무조건 허용하지 않고, 작성된 가이드가 있는 조합을 UI에 표시한다.

초기 방향 선택은 좌상 315°·우상 45°·왼쪽 270°·오른쪽 90° 중
장면이 지원하는 프리셋으로 한정한다. 연속 각도와 광원 높이 조절은
후속 확장으로 두며, 지원되지 않는 조건에는 정확한 가이드처럼 보이는
결과를 자동 생성하지 않는다.

### 2D 장면에서 가이드를 만드는 방법

평면 선화만으로 정확한 물체 형상, 가려짐, 투영 그림자를 추론할 수 없다.
MVP는 **장면별로 제작한 영역·명암 마스크 + 조명별 채색 레시피**를 사용한다.
그림자 마스크를 단순 회전시키는 방식은 사용하지 않는다.

1. 장면별로 광원을 받을 면, 그늘, 흰색을 남길 영역을 지정한다.
2. 지원하는 방향별로 투영 그림자를 작성한다.
3. 시간대와 광원 종류에 맞춰 팔레트, 명도 단계, 수분량, 채색 순서를 결합한다.
4. 실제 연습에 쓰는 최종 `GuideDefinition`에 장면·가이드 버전과
   구체적인 `LightingSettings`를 고정한다.

현재는 직접 작성한 방향별 명암과 장면 영역에 시간대·광원별 레시피를
결합한다. 지원하는 264조합만 UI에 제공한다. 영역의 법선·깊이·높이를
가진 2.5D 데이터와 동적 조명은 별도 실험 단계로 둔다.

## 5. 단계별 채색 가이드

가이드는 영역 표시와 함께 **무엇을, 왜, 어떤 순서로 칠하는지** 설명한다.
각 단계는 다음 정보를 가진다.

- 대상 영역 ID와 흰색을 남겨야 할 영역 ID.
- 추천 색과 혼색 설명. 검정색을 더하는 것만으로 그림자를 설명하지 않는다.
- 디지털 붓의 수분·안료·불투명도 시작값.
- 워시, 그라데이션, 웻온웻, 글레이징, 드라이브러시, 리프팅 중 기법.
- 밝은 면·그늘 오버레이와 완료 판단 힌트.

예: **실내 장면 / 오후 / 우상단 자연광**

| 단계 | 행동 | 이유 |
| --- | --- | --- |
| 1 | 옅은 노란 바탕을 넓게 깔고 밝은 면은 남긴다 | 전체 분위기를 통일하고 종이의 밝기를 보존한다 |
| 2 | 식물과 의자의 큰 색면을 얇게 나눈다 | 세부 묘사 전에 물체의 관계를 정리한다 |
| 3 | 빛의 반대쪽 면과 접촉 그림자를 칠한다 | 광원의 위치와 물체의 부피를 드러낸다 |
| 4 | 마른 색 위에 투명한 어두운 색을 겹친다 | 바탕색을 살리며 명암을 깊게 한다 |
| 5 | 좁은 디테일을 더하고 가이드를 끈다 | 전체 대비와 남겨진 밝은 부분을 확인한다 |

단계 진행은 사용자가 완료 표시를 하는 방식으로 시작한다. 자동 채점이나
‘정답 그림과 픽셀 일치’ 평가는 후속 검토 사항이다. 힌트 오버레이는
사용자의 그림 데이터에 섞지 않고 PNG 내보내기에서도 제외한다.

## 6. Apple Pencil과 터치 입력

입력은 표준 [Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)를 사용한다.
[WebKit의 iPadOS 안내](https://webkit.org/blog/10247/new-webkit-features-in-safari-13-1/)도
기능 감지와 Pointer Events 사용을 권장한다. 실제 지원 범위와 필압은
아이패드·Pencil 모델·Safari 조합에서 검증한다.

- `pointerType === 'pen'`이면 그리기, 손가락은 화면 이동·확대에 사용한다.
- 기본 펜 전용 모드는 손가락 채색을 막아 손바닥이 닿아도 선을 남기지 않는다.
  손가락 접촉을 손바닥과 완벽히 구분하는 웹 API는 가정하지 않는다.
- 펜 입력 중에는 터치 기반 뷰포트 변환을 일시 정지한다. 별도 이동 모드와
  명시적인 두 손가락 제스처로 화면을 조작한다.
- 압력은 붓 크기와 안료량에 연결하고, 기울기는 지원 장치에서만 보조 사용한다.
  필압 미지원 펜이나 마우스에는 기본 크기·농도를 제공한다.
- `setPointerCapture`로 스트로크를 추적하고, `pointerup`, `pointercancel`,
  `lostpointercapture`와 페이지 전환 시 입력 상태를 정리한다.
- 그리기 표면에만 `touch-action: none`을 적용한다. 페이지 전체의
  확대·스크롤이나 접근성을 막지 않는다.
- [getCoalescedEvents](https://developer.mozilla.org/en-US/docs/Web/API/PointerEvent/getCoalescedEvents)는
  기능 감지 후 사용하고, 미지원 환경은 `pointermove` 샘플로 보간한다.
- hover, Pencil squeeze, double-tap 등 네이티브 전용 동작은 필수 기능으로 삼지 않는다.

포인터 좌표는 캔버스의 이동·확대 변환을 역으로 적용해 논리 좌표로 바꾼다.
저장하는 좌표는 0–1로 정규화하고, 디스플레이 배율과 분리한다.

## 7. 수채화 표현과 렌더링

MVP의 목표는 빠르게 그릴 수 있는 투명한 워시와 겹칠하기이다.
Canvas 2D에서 질감이 있는 붓 스탬프, 농도 변화, 가장자리의 약한 번짐,
마른 레이어 위 글레이징을 구현한다. 실제 물·안료의 유체 시뮬레이션은
초기 범위에 포함하지 않는다.

레이어 순서:

```text
종이 배경 → 초기 바탕색 → 사용자 채색 레이어 → 선화 → 가이드/커서
```

바탕색·선화는 보호하고, 지우개는 사용자 레이어에만 작동한다.
PNG는 종이·바탕색·사용자 채색·선화를 합성하고 가이드와 커서를 제외한다.

입력 이벤트는 샘플 수집에 집중하고 `requestAnimationFrame`에서 그린다.
React는 도구와 가이드 상태를 담당하며 스트로크의 매 샘플을 React 상태로
전달하지 않는다. 현재 논리 캔버스는 1000×760 px다. 실기기 측정으로 해상도를 조정한다. 화면용 backing store는 DPR과 총 픽셀 예산을
함께 제한하고, 모든 레이어를 무조건 최대 해상도로 만들지 않는다.

성능 목표는 기준 아이패드에서 보통 스트로크를 그릴 때 60 fps에 가깝게
유지하는 것이다. 지원 기기, 입력 지연, 메모리 한계는 측정 전 확정하지 않는다.
WebGL, Worker, OffscreenCanvas는 필요할 때 기능 감지를 전제로 추가한다.

## 8. 기술 구조와 데이터 흐름

| 영역 | 선택 | 목적 |
| --- | --- | --- |
| 앱 UI | React + TypeScript | 패널·설정·가이드와 데이터 계약 |
| 개발/빌드 | Vite | 정적 웹 앱 개발과 배포 산출물 |
| 드로잉 | 독립 TypeScript + Canvas 2D | UI와 입력·렌더링 분리 |
| 콘텐츠 | 타입이 있는 카탈로그와 정적 자산 | 서버 없이 배경·프리셋 제공 |
| 저장 | IndexedDB | 연습 메타데이터·스트로크·체크포인트 |
| 설치/오프라인 | Web App Manifest + Service Worker | 홈 화면 실행과 선택한 자산 캐시 |

```text
content + domain
       ↓
features: 배경 선택 → 조명 설정 → 가이드 확인 → 작업 공간
                                              ↓
                                     input → brush → renderer
                                              ↓
                                           history
                                              ↓
                                     platform/storage
```

`domain`은 React와 브라우저 API에 의존하지 않는다. `engine`도 React에서
분리한다. `features`가 화면과 엔진을 연결하고, `platform`은 저장과
브라우저 수명 주기를 다룬다. 현재는 사용자 계정과 백엔드 없이 시작한다.
자세한 파일 위치는 [폴더 구조](folder-structure.md)에 정리했다.

## 9. 연습 저장과 복구

`PracticeSession`은 장면·가이드·렌더러 버전, 조명 설정, 붓 설정과
시드가 있는 스트로크, 실행 취소 위치를 저장한다. 그림의 재생을
일관되게 하기 위해 붓의 무작위 질감은 시드로 고정한다.

- 스트로크 완료 후 짧은 디바운스로 자동 저장하고 저장 상태를 표시한다.
- 실행 취소/다시 실행은 스트로크 명령 기준으로 처리한다.
- 현재는 누적 Canvas와 스트로크 재생을 사용한다. 주기적인 래스터 체크포인트는
  후속 최적화이며 원본 명령을 대체하지 않는다.
- 저장 스키마를 버전 관리하고, 알 수 없는 버전은 조용히 덮어쓰지 않는다.
- 채색 후 조명이나 장면을 바꿀 때 기존 연습은 보존하고 새 연습을 만든다.
- 페이지 종료 시점에만 저장을 의존하지 않는다. 백그라운드 전환 전까지
  완료된 스트로크를 저장하고, 갑작스러운 종료의 손실 범위를 줄인다.
- [브라우저 저장 공간과 제거 정책](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)을
  고려해 용량 초과를 처리하고, 로컬 프로젝트 백업 기능을 제공한다.

프로젝트 내보내기는 `aqua-canvas-practice` 버전 1 JSON이다. 장면·조명·가이드
버전, 바탕색 표시, 시드와 붓 설정이 있는 스트로크, undo 위치를 포함한다.
가져오기는 16 MB 이하이며 좌표·색·버전·지원 조합을 검증한다. PNG는 결과 공유용이며
편집 가능한 연습 저장 형식을 대체하지 않는다.

## 10. PWA와 자산 제공

MVP는 정적 호스팅의 HTTPS 웹 앱으로 제공한다. manifest·아이콘·Service Worker를 구현했으며 홈 화면 설치와 실제 오프라인
동작은 HTTPS의 iPad Safari에서 확인할 수용 조건으로 남긴다.

초기 캐시에는 앱 셸과 작은 메타데이터를 넣는다. 큰 배경과 가이드는
선택한 장면 단위로 내려받고 캐시 버전을 관리한다. 약 5.9 MB의 참고
영상은 앱 초기 로딩과 필수 캐시에서 제외하고 사용자가 재생할 때 읽는다.
오프라인 상태에서는 준비된 장면만 연습할 수 있도록 표시한다.

## 11. 구현 순서와 완료 조건

| 단계 | 내용 | 완료 조건 |
| --- | --- | --- |
| 0 — 준비 | 구조·타입·문서·원본 영상·개발 준비 화면 | 타입 검사와 프로덕션 빌드 통과, 영상 경로 확인 |
| 1 | 영상 속 장면 1종과 기본 펜 엔진 | 아이패드에서 선택·필압 채색·지우기·undo/redo 가능 |
| 2 | 시간대 5종과 지원 광원/방향별 가이드 | 조명 변경에 따라 영역·팔레트·순서가 함께 달라짐 |
| 3 | 창가 정물·호숫가 추가, 저장·내보내기 | 3종의 배경을 선택하고 재접속 후 이어 그리기 가능 |
| 4 | 설치·오프라인·나머지 배경 | 캐시한 장면 연습, 업데이트 후 기존 연습 복원 |

### 실제 기능 구현 시 검증할 항목

- 아이패드 Safari에서 펜으로만 선이 생기고 손바닥 접촉으로 선이 생기지 않는다.
- 같은 좌표의 펜 선이 확대·이동·회전된 화면에서도 배경과 일치한다.
- 필압 차이가 보이고, 미지원 입력도 기본값으로 사용할 수 있다.
- 펜이 캔버스 밖으로 나가거나 이벤트가 취소되어도 그리기 상태가 남지 않는다.
- 광원 방향에 따라 물체의 밝은 면과 투영 그림자 가이드가 맞게 바뀐다.
- 가이드를 끄거나 PNG를 내보내도 가이드 표시가 작품에 남지 않는다.
- undo/redo, 저장·복원 후 같은 붓 질감과 색이 재현된다.
- 장면 자산이 없거나 오프라인일 때 흰 화면 대신 준비 상태를 안내한다.

단위 테스트는 좌표 변환, 스트로크 재생, 이력, 저장 마이그레이션,
가이드 선택 규칙처럼 실제 데이터 손실·잘못된 안내를 막는 영역부터 작성한다.
브라우저 자동화는 화면 흐름과 저장·내보내기를 확인하고, 필압·팜 리젝션·
지연은 실기기에서 별도로 확인한다.

## 12. 후속 결정 사항

영상 속 장면을 앱용으로 정리할 최종 구도, 기본 바탕색의 강도,
첫 지원 아이패드/Pencil 조합, 붓의 질감과 번짐 정도를 시제품으로 확인한다.
초기에는 사용자가 자유롭게 칠하고 가이드를 참고하는 방식을 기본으로 두고,
영역 밖 채색을 막는 초급 모드는 별도 옵션으로 검토한다.

현재는 SVG 139개와 지원 조합 264개를 사용한다. 상세 구현 상태는
[구현 진행표](implementation-plan.md)에 정리한다.
동적 조명, 복수 광원, 실시간 수분 확산, 자동 평가, 계정·클라우드 동기화는
초기 학습 경험이 검증된 뒤 별도 설계한다.
